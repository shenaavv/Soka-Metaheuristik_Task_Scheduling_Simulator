Penjadwalan Task ke VM dengan Algoritma Heuristik

Di cloud, banyak task harus dibagi ke beberapa Virtual Machine (VM) yang kecepatannya berbeda-beda. Jumlah kombinasi pembagiannya sangat besar (MN), sehingga dipakai algoritma meta-heuristik untuk mencari jadwal yang mendekati optimal dalam waktu singkat.

Tujuan 1Meminimalkan makespan: waktu hingga task terakhir selesai.
Tujuan 2Memaksimalkan utilisasi VM agar tidak ada VM yang menganggur.
Tujuan 3Menekan ketimpangan beban (degree of imbalance) antar VM.
Genetic Algorithm (GA)Berbasis evolusi: seleksi, crossover, mutasi pada populasi jadwal.
Modified Bat Algorithm (MBA)Berbasis perilaku kelelawar: frekuensi, loudness, dan pulse rate dengan penyesuaian untuk ruang diskrit.

Cara memakai halaman ini

Baca teori di tiap menu, lalu buka Simulasi untuk menjalankan kedua algoritma pada data task acak yang sama dan membandingkan hasilnya.

01 · Formulasi

Model Masalah

Ada N task (panjang Li dalam MI) dan M VM (kecepatan Sj dalam MIPS). Sebuah jadwal adalah vektor x dengan xi ∈ {0..M−1} yang menyatakan VM tujuan task i.

Representasi solusi

Task :  T0 T1 T2 T3 T4 T5
x    : [ 2  0  1  0  2  1 ]   → T0,T4 ke VM2 ; T1,T3 ke VM0 ; T2,T5 ke VM1

Rumus metrik

Beban VM j : Load(j) = Σ Li / Sj (untuk semua i dengan xi = j)
Makespan : MS = maxj Load(j)
Utilisasi : U = Σj Load(j) / (M × MS) × 100%
Imbalance : DI = (max Load − min Load) / rata-rata Load
Fitness GA : f = 1 / MS (MS makin kecil → f makin besar)

Contoh hitung singkat

Task L = [400, 600, 500, 300] pada 2 VM (S = 100 dan 200). Jadwal x = [0, 1, 1, 0]: Load(0) = (400+300)/100 = 7 s; Load(1) = (600+500)/200 = 5,5 s. Maka MS = 7 s, U = 12,5/(2×7) = 89,3%, DI = (7−5,5)/6,25 = 0,24.

Asumsi simulasi

  • Task independen dan non-preemptive.
  • VM heterogen (kecepatan berbeda) dan jumlah VM tetap.
  • Waktu transfer data diabaikan.

02 · Algoritma

Genetic Algorithm

Terinspirasi seleksi alam Darwin. Sekumpulan jadwal (populasi) berevolusi: jadwal yang lebih baik lebih sering dipilih sebagai induk, lalu dikawinkan untuk menghasilkan jadwal baru.

Alur

1. InisialisasiPopulasi P jadwal acak.
2. EvaluasiHitung MS dan fitness tiap kromosom.
3. SeleksiTournament k=3: ambil yang MS terkecil dari 3 kandidat acak.
4. CrossoverUniform: tiap gen diambil dari induk 1 atau 2 secara acak (peluang pc).
5. MutasiTiap gen dipindah ke VM acak dengan peluang pm.
6. Elitisme2 jadwal terbaik selalu lolos ke generasi berikutnya.

Pseudocode

P ← populasi acak
ulangi sampai iterasi maks:
    hitung fitness semua x ∈ P
    P' ← {elite terbaik}
    selama |P'| < |P|:
        a, b ← tournament(P), tournament(P)
        c ← crossover(a, b)  jika rand < pc, selain itu c ← a
        mutasi(c, pm)
        tambahkan c ke P'
    P ← P'
kembalikan solusi terbaik

Parameter yang dipakai di simulasi

ParameterNilaiFungsi
Ukuran populasi30Keragaman solusi
pc0,8Peluang crossover
pm0,02Peluang mutasi per gen
Elitisme2Menjaga solusi terbaik

Kelebihan & kekurangan

  • + Eksplorasi luas dan stabil lewat populasi besar dan mutasi.
  • + Mudah diadaptasi ke berbagai fungsi objektif.
  • − Konvergensi cenderung lebih lambat dan butuh banyak evaluasi fitness.
  • − Sensitif terhadap pengaturan pc, pm, dan ukuran populasi.

03 · Algoritma

Modified Bat Algorithm

Terinspirasi ekolokasi kelelawar. Setiap kelelawar adalah satu jadwal yang terbang menuju jadwal terbaik (global best), sementara loudness dan pulse rate mengatur keseimbangan eksplorasi dan eksploitasi.

Analogi

KelelawarPenjadwalan
PosisiVektor jadwal x
Frekuensi f ∈ [0,1]Seberapa kuat jadwal meniru global best
Loudness APeluang menerima solusi baru; menurun tiap iterasi
Pulse rate rPeluang melakukan local search; meningkat tiap iterasi
MangsaJadwal dengan makespan terkecil

Persamaan inti (versi kontinu → disesuaikan ke diskrit)

fi = fmin + (fmax − fmin) × β , β ∈ [0,1]
vi(t+1) = vi(t) + (xi − x*) × fi ; xi(t+1) = xi(t) + vi(t+1)
A(t+1) = α·A(t) ; r(t+1) = r(0)·(1 − e−γt)

Pada ruang diskrit, "bergerak ke x*" diterjemahkan menjadi: tiap gen disalin dari global best dengan peluang yang bergantung pada f dan kemajuan iterasi.

Pseudocode

inisialisasi kelelawar x_i, A=1, r=r0 ; x* ← terbaik
ulangi sampai iterasi maks:
    untuk tiap kelelawar i:
        f ← acak[0,1]
        x' ← salin gen dari x* dengan peluang p(f, iterasi)
        jika rand > r:  x' ← local search di sekitar x* (pindah 1-2 task)
        jika MS(x') < MS(x_i) dan rand < A:
            x_i ← x' ; A ← α·A ; r ← r0(1 − e^(−γt))
        perbarui x* jika x_i lebih baik
kembalikan x*

Parameter yang dipakai di simulasi

ParameterNilai
Jumlah kelelawar30
A awal / α1,0 / 0,97
r awal / γ0,3 / 0,1

Kelebihan & kekurangan

  • + Konvergen cepat karena tarikan kuat ke global best.
  • + Local search terarah memperhalus solusi di fase akhir.
  • − Rawan terjebak optimum lokal bila keragaman populasi cepat hilang.
  • − Perlu modifikasi untuk masalah diskrit seperti penjadwalan.

Kesimpulan awal

MBA biasanya unggul pada kecepatan menurunkan makespan, sedangkan GA lebih tahan terhadap konvergen prematur. Buktikan sendiri di menu Simulasi: jalankan beberapa kali karena hasil bersifat acak.
